# План обновления MMSS по Agent Skills

## Цель

Извлечь и сопоставить все доступные инструкции скиллов и материалы Agent Skills plugin с текущими контрактами MMSS; подготовить проверяемый MMSS-json и на его основе предложить совместимое обновление MMSS-скиллов репозитория. Этот документ описывает предстоящую работу, а не заявляет, что полное извлечение или обновление уже выполнено.

## Основание и текущий контекст

- Первичный маршрут: `mmss-skill-router`; архитектурная основа: составной `mmss-principle-synthesis` v0.3.0.
- Для планирования использован `planning-and-task-breakdown` из локального Agent Skills plugin.
- Для последующего сбора/синтеза выделены `skill-quick-sampler` (инвентаризация), `data-to-skill` и `data-to-skill-transformer` (извлечение механизмов), `mmss-adaptive-sp-combinator` и `mmss-skill-boundary-combinator` (сопоставление границ и композиция), `mmss-schema-guided-agent-bridge` (структура/валидация JSON). Это роли в плане, не утверждение, что полное выполнение этих скиллов уже состоялось.
- Рабочая база: `skills/` содержит 12 каталогов MMSS (включая составной и монолитный варианты), README перечисляет 10 связанных standalone пакетов; версии находятся в диапазоне 0.1.0–0.3.0, монолитная редакция — 0.1.5.
- Кэш v0.6.10 содержит 25 skills; upstream `main` зафиксирован на commit `eb07f19f52c2669f2364897aaa293e2aaddd7b1c`, manifest v0.6.14. Имена совпадают, все 25 тел `SKILL.md` различаются по SHA-256.
- Upstream snapshot содержит 7 общих references, 7 supporting assets внутри skills, 9 slash-команд, 4 personas и 17 integration/setup документов, а также host adapters, scripts, hooks и evals. Эти слои учтены отдельно.
- Все 25 skill-текста, 7 общих references, 7 supporting assets, 9 команд и 4 personas прошли полный text scan и структурное извлечение. Integration docs и host trees полностью инвентаризированы; семантический разбор каждого host guide не входит в минимальный перенос.
- Основные смысловые изменения между v0.6.10 и v0.6.14 внесены в MMSS-json; line deltas являются ориентировочными.
- В репозитории на момент планирования нет `tasks/plan.md` или `tasks/todo.md`; локальные `AGENTS.md` не найдены; git working tree чистый.

## Решения по архитектуре и границам

1. Сначала зафиксировать снимок и происхождение набора источников, чтобы версии и происхождение каждой рекомендации были восстанавливаемы.
2. Получать полный текст каждого `SKILL.md` и каждого общего reference; README и метаданные использовать только для маршрутизации/сверки инвентаря.
3. Сформировать единый MMSS-json как отчет/предлагаемый patch: реестр источников, принципы/механизмы с locators, перекрёстную карту к текущим скиллам, зависимости и конфликты, рекомендации изменений, совместимость и проверки. Не приписывать плагину авторство над синтезированными структурами.
4. Сохранять `value`, `convention`, `context` на переходах представления; отдельно различать наблюдение источника, интерпретацию, требование и проектное решение.
5. Не копировать автоматически команды, интеграции, установки или runtime-поведение в MMSS: переносить только применимые и подтверждённые инструкциями механизмы, указывая требования хоста и ограничения.
6. Обновление отдельных скиллов — отдельный последующий этап с таблицей совместимости и версиями по реальному классу изменения. Не объединять составной v0.3.0 и монолитный v0.1.5 без решения о поддержке/миграции.

## Этапы и задачи

### Этап 1 — Снимок источников и спецификация

- [x] **Задача 1. Зафиксировать инвентарь и метаданные источников.** Снять список путей, имён, frontmatter, версии, README/upstream claims, references, команд и адаптеров; записать локальный путь/идентификатор версии и дату снимка.
  - Критерии: каждый обнаруженный файл отнесён к типу (skill/reference/plugin integration/docs); совпадение 25 имен и различие всех 25 текстов кэша/upstream зафиксированы; отсутствующие/нечитаемые материалы явно перечислены.
  - Проверка: автоматическая сверка числа каталогов и файлов + ручной просмотр несовпадений.
  - Зависимости: нет.
- [x] **Задача 2. Зафиксировать контракт MMSS-json и критерии приёма.** Определить стабильные поля и схему записи evidence/principle/skill mapping/change recommendation/validation, не нарушая текущий конверт базового MMSS.
  - Критерии: обязательные поля, типы, ID, локаторы, статусы охвата и совместимость заданы; неизвестное представимо без выдумывания.
  - Проверка: примеры для полного, частичного и недоступного источника проходят структурную проверку схемы.
  - Зависимости: Задача 1.

### Этап 2 — Полное извлечение и карта покрытия

- [x] **Задача 3. Извлечь все 25 skill-инструкций Agent Skills.** Для каждой инструкции зафиксировать описание/триггер, workflow outline, проверочные критерии, supporting files, locator и hash.
  - Критерии: coverage-реестр содержит по одному source record на каждый из 25 skills и точный locator/hash; каждый извлечённый механизм отличён от source description; никаких выводов только по имени.
  - Проверка: сверка полного списка каталогов с числом карточек и выборочный повторный просмотр source locators.
  - Зависимости: Задачи 1–2.
- [x] **Задача 4. Извлечь 7 общих references, 7 supporting assets и возможности плагина.** Сопоставить reference-файлы с инструкциями, командами, personas, манифестом и integration surfaces.
  - Критерии: семь references учтены; команды/интеграции помечены как plugin-level контекст; отсутствующие реализации и неподтверждённый upstream статус помечены.
  - Проверка: матрица «утверждение → источник → локальный артефакт → статус подтверждения».
  - Зависимости: Задачи 1–3.
- [x] **Задача 5. Построить карту навыков, version delta и перекрёстное MMSS-сопоставление.** Выделить lifecycle-кластеры, общие механизмы, отличия 0.6.10→0.6.14, зависимости и переносимые/host-specific границы для текущих MMSS пакетов.
  - Критерии: каждое предложение изменения связано с конкретными source IDs и целевым MMSS-файлом; различены перенос, адаптация, сохранение как есть и отказ от переноса.
  - Проверка: независимая ручная проверка покрытия всех исходников и таблицы соответствий.
  - Зависимости: Задачи 3–4.

### Этап 4 — Валидация и передача на реализацию

  - Критерии: нет необъяснённых пропусков; неисследованные материалы явно перечислены; проверки имеют статусы и область; backlog можно исполнять без повторного выяснения границ.

Задачи 3 и 4 могут идти независимо после стабилизации реестра/контракта, но обе блокируют карту покрытия. В рамках текущего этапа подготовлен план; параллельная делегация не запускалась.

## Контрольные точки

- **После этапа 1:** закрытый список источников и согласованный формат MMSS-json.
- **После этапа 2:** coverage 25/25 skills + 7/7 shared references + 7 supporting assets; завершена карта plugin surfaces и отличий версий.
- **После этапа 3:** валидный предлагаемый JSON patch и набор обновлений с оценкой совместимости.
- **Финал:** структура/ссылки проверены; статус применения остаётся `not_applied`, пока отдельная реализация не выполнена.

## Риски и меры

| Риск | Влияние | Мера |
|---|---|---|
| Между кэшем v0.6.10 и upstream v0.6.14 изменились все skill тексты | Пропустить новые механизмы | Сверить SHA-256 всех 25 файлов и хранить pinned commit и version-delta summary. |
| Объём 25 skills, references и supporting assets | Поверхностное извлечение/потеря provenance | Держать поэлементный реестр, группировать работу по lifecycle, сохранять locators и coverage status. |
| Похожие процессы имеют разные контракты и критерии | Несовместимое слияние и потеря boundary identity | Сопоставлять значения, convention и context; сохранять противоречия до их разрешения. |
| Plugin commands и host adapters ошибочно принять за portable skill semantics | Некорректные обязательства в MMSS | Хранить plugin-level capabilities отдельным слоем; проверять фактическую доступность хоста перед рекомендацией. |
| Изменение core затрагивает JSON-интерфейсы и две редакции | Нарушение совместимости | Сначала предложить patch и migration map; версионировать по изменённому контракту, монолитную редакцию рассматривать отдельно. |
| Размер полного извлечения | Задачи становятся XL | Выполнять этапами с контрольными точками; при реализации резать по lifecycle-кластерам и файлам, не по одной огромной задаче. |

## Допущения и открытые вопросы

- Источником истины выбран upstream snapshot v0.6.14; локальный кэш v0.6.10 использован для сравнения.
- Scope: 25 skills, 7 общих references, 7 supporting assets, 9 commands, 4 personas, 17 setup/integration docs и integration directories.
- Редактирование skill-контрактов является отдельной реализацией; текущий результат содержит предложения и implementation-ready targets. Composite и monolithic редакции оценены раздельно.

## Граница текущего результата

Задачи плана исполнены: построены source inventory, MMSS-json, version-delta summary и предложения по изменениям. Skill-файлы MMSS не редактировались в пределах данного плана; поведенческая оценка не выполнялась.
